# Semantic Knowledge Graph

## Overview

Entities and typed relations expand around a question while evidence paths distinguish fact from inference.

## Metadata

- Collection: Interfaces and Information Systems
- Medium: HTML, SVG, Canvas, WebGL, or composited media
- Best for: research, concepts, search, and relationship reasoning
- Complexity: Moderate to advanced

## Signature Features

- Center a specific question, separate entity types visibly, label relations, and attach evidence or confidence to each edge.
- Expand only relevant neighbors, trace answer paths, collapse detours, and distinguish retrieved facts from inferred links.
- For **Semantic Knowledge Graph**, use a near-black, slate, or warm-white operational surface with one semantic accent and color reserved for status, confidence, or ownership.

## Style Prompt

Create a polished HTML animation in the **Semantic Knowledge Graph** style. Center a specific question, separate entity types visibly, label relations, and attach evidence or confidence to each edge. Expand only relevant neighbors, trace answer paths, collapse detours, and distinguish retrieved facts from inferred links. Use a disciplined operational surface with color assigned consistently to status, confidence, ownership, or risk. Set typography in a compact UI sans serif or monospaced face; align values, units, timestamps, and labels to a stable grid. Organize the message around the operational decision so every state change, alert, route, or dependency has a readable cause.

Adapt subject matter, wording, duration, and aspect ratio to the user's material. Preserve supplied text unless rewriting is requested, and simplify secondary detail before compromising the defining construction logic.

## Customizable Elements

- Adjust scenario, data density, update cadence, annotation depth, alert severity, and the balance between overview and inspection.
- Change layout, status palette, map or graph scale, and viewpoint without breaking units, chronology, topology, or state semantics.

## Avoid

- Avoid unlabeled node clouds, force-layout jitter, unsupported relationships, or equating visual proximity with truth.
- Do not add dashboard chrome, alerts, metrics, or map layers that do not support the operational decision being shown.
- Keep essential text outside dense movement and preserve a clear reduced-motion end state.
