# Cybersecurity Threat Map

## Overview

Suspicious events move from source to target while confidence, severity, and defensive containment remain explicit.

## Metadata

- Collection: Interfaces and Information Systems
- Medium: HTML, SVG, Canvas, WebGL, or composited media
- Best for: security operations, attacks, defense, and incident response
- Complexity: Moderate to advanced

## Signature Features

- Organize events by source, target, asset criticality, confidence, and response stage rather than geography alone.
- Correlate low-level events into an incident, show lateral movement only when evidenced, and close paths as controls contain them.
- For **Cybersecurity Threat Map**, use a near-black, slate, or warm-white operational surface with one semantic accent and color reserved for status, confidence, or ownership.

## Style Prompt

Create a polished HTML animation in the **Cybersecurity Threat Map** style. Organize events by source, target, asset criticality, confidence, and response stage rather than geography alone. Correlate low-level events into an incident, show lateral movement only when evidenced, and close paths as controls contain them. Use a disciplined operational surface with color assigned consistently to status, confidence, ownership, or risk. Set typography in a compact UI sans serif or monospaced face; align values, units, timestamps, and labels to a stable grid. Organize the message around the operational decision so every state change, alert, route, or dependency has a readable cause.

Adapt subject matter, wording, duration, and aspect ratio to the user's material. Preserve supplied text unless rewriting is requested, and simplify secondary detail before compromising the defining construction logic.

## Customizable Elements

- Adjust scenario, data density, update cadence, annotation depth, alert severity, and the balance between overview and inspection.
- Change layout, status palette, map or graph scale, and viewpoint without breaking units, chronology, topology, or state semantics.

## Avoid

- Avoid anonymous red beams across a globe, fear-driven flashing, attribution without evidence, or treating all traffic as malicious.
- Do not add dashboard chrome, alerts, metrics, or map layers that do not support the operational decision being shown.
- Keep essential text outside dense movement and preserve a clear reduced-motion end state.
