# Mission-Control Telemetry

## Overview

Multiple synchronized telemetry channels, event clocks, and state indicators converge on one mission timeline.

## Metadata

- Collection: Interfaces and Information Systems
- Medium: HTML, SVG, Canvas, WebGL, or composited media
- Best for: spaceflight, launches, complex operations, and critical decisions

## Signature Features

- Divide a deep neutral console into a master event clock, restrained channel plots, state blocks, and one mission trajectory.
- Synchronize every graph to mission time; let threshold crossings trigger procedural state changes and camera attention.
- For **Mission-Control Telemetry**, use a near-black, slate, or warm-white operational surface with one semantic accent and color reserved for status, confidence, or ownership.

## Style Prompt

Create a polished HTML animation in the **Mission-Control Telemetry** style. Divide a deep neutral console into a master event clock, restrained channel plots, state blocks, and one mission trajectory. Synchronize every graph to mission time; let threshold crossings trigger procedural state changes and camera attention. Use a disciplined operational surface with color assigned consistently to status, confidence, ownership, or risk. Set typography in a compact UI sans serif or monospaced face; align values, units, timestamps, and labels to a stable grid. Organize the message around the operational decision so every state change, alert, route, or dependency has a readable cause.

## Avoid

- Avoid sci-fi HUD clutter, arbitrary waveforms, flashing every panel, or telemetry that disagrees with the event clock.
- Do not add dashboard chrome, alerts, metrics, or map layers that do not support the operational decision being shown.
