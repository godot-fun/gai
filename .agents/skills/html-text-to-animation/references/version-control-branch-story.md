# Version-Control Branch Story

## Overview

Commits split into branches, diverge, merge, conflict, and resolve along a readable development history.

## Metadata

- Collection: Interfaces and Information Systems
- Medium: HTML, SVG, Canvas, WebGL, or composited media
- Best for: software, collaboration, alternatives, and reconciliation
- Complexity: Moderate to advanced

## Signature Features

- Lay commits on a left-to-right graph with named branches, authors, tags, merge parents, and a readable working head.
- Create commits discretely, fork branches at real ancestors, expose conflicts at merge, and resolve them without erasing history.
- For **Version-Control Branch Story**, use a near-black, slate, or warm-white operational surface with one semantic accent and color reserved for status, confidence, or ownership.

## Style Prompt

Create a polished HTML animation in the **Version-Control Branch Story** style. Lay commits on a left-to-right graph with named branches, authors, tags, merge parents, and a readable working head. Create commits discretely, fork branches at real ancestors, expose conflicts at merge, and resolve them without erasing history. Use a disciplined operational surface with color assigned consistently to status, confidence, ownership, or risk. Set typography in a compact UI sans serif or monospaced face; align values, units, timestamps, and labels to a stable grid. Organize the message around the operational decision so every state change, alert, route, or dependency has a readable cause.

Adapt subject matter, wording, duration, and aspect ratio to the user's material. Preserve supplied text unless rewriting is requested, and simplify secondary detail before compromising the defining construction logic.

## Customizable Elements

- Adjust scenario, data density, update cadence, annotation depth, alert severity, and the balance between overview and inspection.
- Change layout, status palette, map or graph scale, and viewpoint without breaking units, chronology, topology, or state semantics.

## Avoid

- Avoid subway-map decoration, branches with no ancestry, rewritten history without notice, or merges drawn as simple crossfades.
- Do not add dashboard chrome, alerts, metrics, or map layers that do not support the operational decision being shown.
- Keep essential text outside dense movement and preserve a clear reduced-motion end state.
